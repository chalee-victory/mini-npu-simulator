# Mini NPU Simulator

AI가 계산하는 방식(MAC 연산)을 흉내 내는 작은 Python 콘솔 계산기입니다.
숫자 배열로 된 입력 패턴을 십자가(Cross) 필터와 X 필터에 각각 곱하고 더해(MAC) 점수를 구하고,
점수를 비교해 패턴이 어느 모양에 더 가까운지 판정합니다.

> 이 문서는 작업이 진행되면서 계속 업데이트됩니다. (현재: 3단계 모드 2 data.json 분석 구현 완료)

## 실행 환경

- Python 3.8 이상
- 외부 라이브러리 없이 표준 라이브러리(`json`, `os`, `time`)만 사용

## 실행 방법

```bash
python main.py
```

실행 후 모드를 선택합니다. 1 또는 2가 아닌 값을 입력하면 다시 선택하라는 안내가 나옵니다.

1. 사용자 입력 (3×3): 필터 A, B와 패턴을 콘솔에 직접 입력
2. data.json 분석: `data.json`의 필터와 패턴을 읽어 일괄 판정

`data.json`은 `main.py`와 같은 폴더에 두어야 합니다. 프로그램은 `main.py` 위치를 기준으로 파일을 찾으므로, 다른 폴더에서 실행해도 동작합니다.

### 의도적 오류 데이터로 실행

`bad_data.json`에는 크기 불일치, 라벨 오류, 키 형식 오류 등을 일부러 넣어 두었습니다. 아래 명령으로 메뉴 없이 모드 2 분석만 실행할 수 있습니다.

```bash
python -c "import main; main.run_mode2('bad_data.json')"
```

### 모드 1 입력 예시

각 줄에 숫자 3개를 공백으로 구분해 입력합니다.

```
필터 A (3줄 입력, 공백 구분)
0 1 0
```

## 구현 요약

### 필터와 패턴

- **필터**: 판정의 기준이 되는 배열입니다. Cross 모양 기준, X 모양 기준처럼 미리 정해 둡니다.
- **패턴**: 판정받을 입력 배열입니다.
- 패턴 하나를 필터 두 개에 각각 MAC 연산해 점수를 구하고, 점수가 더 높은 필터의 이름으로 판정합니다.

### MAC 연산: `mac(pattern, flt)`

- 입력 패턴과 필터를 같은 위치(`i`행 `j`열)끼리 곱한 뒤 모두 더해 점수를 반환합니다.
- NumPy 같은 외부 라이브러리 없이 이중 `for` 반복문으로 직접 구현했습니다.
- `len(pattern)`으로 크기 N을 구하므로 3×3부터 25×25까지 크기와 상관없이 동작합니다.
- N×N 배열이면 곱셈과 덧셈을 각각 N²번 수행합니다.

### 라벨 정규화: `normalize_label(label)`

데이터에 섞여 있는 여러 표기를 프로그램 내부의 표준 라벨 두 가지(`Cross`, `X`)로 통일합니다.

| 입력 표기 | 표준 라벨 |
|---|---|
| `+`, `cross` (대소문자, 앞뒤 공백 무관) | `Cross` |
| `x` (대소문자, 앞뒤 공백 무관) | `X` |
| 그 밖의 값 | `None` (호출한 쪽에서 라벨 오류로 처리) |

- 먼저 `strip()`으로 앞뒤 공백을 지우고 `lower()`로 소문자로 바꾼 뒤, 대응표(`LABEL_MAP`)에서 찾습니다.
- 대응표에서 `get()`으로 찾기 때문에, 알 수 없는 라벨이 들어와도 오류로 멈추지 않고 `None`을 반환합니다.

### 판정과 동점 처리: `judge(score_a, score_b, label_a, label_b)`

- 컴퓨터는 소수를 2진수로 정확히 저장하지 못해 `0.9`와 `0.8999999999999999`처럼 사실상 같은 값에 미세한 차이가 생깁니다.
- 그래서 `abs(score_a - score_b) < 1e-9`이면 동점(`UNDECIDED`)으로 판정하는 허용오차(epsilon) 정책을 적용했습니다.
- 동점 검사를 가장 먼저 수행합니다. 크기 비교(`>`)를 먼저 하면 미세한 차이만으로 한쪽이 이긴 것으로 판정되기 때문입니다.
- 이긴 쪽 이름을 매개변수(`label_a`, `label_b`)로 받아, 모드 1(`A`/`B`)과 모드 2(`Cross`/`X`)에서 같은 함수를 사용합니다.

### 모드 1 입력과 검증: `read_matrix(name, n=3)`

n줄을 한 줄씩 입력받아 n×n 실수(float) 배열로 반환합니다. 필터 A, 필터 B, 패턴 입력에 같은 함수를 사용합니다.

- 한 줄을 입력받을 때마다 두 가지를 순서대로 검사합니다.
  1. **열 개수**: `split()`으로 나눈 조각이 n개가 아니면 오류
  2. **숫자 형식**: 각 조각을 `float()`로 바꾸다 `ValueError`가 나면 오류 (`try / except`로 처리해 프로그램이 멈추지 않음)
- 오류가 나면 원인(입력된 개수 또는 입력값)과 몇 번째 줄인지를 안내하고, `continue`로 **그 줄만** 다시 입력받습니다.
- 검사를 통과한 줄만 저장하고, 정상 줄이 n개 모일 때까지 반복하므로 **행 개수는 항상 n**이 됩니다.
- `split()`을 구분자 없이 사용해 공백이 여러 개이거나 앞뒤에 공백이 있어도 정상 처리합니다.

### 성능 측정: `measure_mac(pattern, flt, repeat=10)`

- `mac()`을 10회 반복 실행한 전체 시간을 `time.perf_counter()`로 재고, 10으로 나눈 뒤 ms 단위로 바꿔 1회 평균 시간을 반환합니다.
- 측정 구간에는 `mac()` 호출만 포함하고, 입력(`input`)과 출력(`print`) 시간은 제외했습니다.
- 모드 2(5×5, 13×13, 25×25)의 성능 분석에서도 같은 함수를 사용할 예정입니다. (4단계)

### 실행 흐름: `main()` → `run_mode1()`

`main()`에서 모드를 선택하면 `run_mode1()`이 다음 순서로 동작합니다.

필터 A, B 입력 → 저장 확인 → 패턴 입력 → MAC 연산 → 연산 시간(평균/10회) → 판정 출력

- 판정 결과가 동점이면 `판정 불가 (|A-B| < 1e-09)`로 출력합니다.

### 모드 2 data.json 분석: `run_mode2(path)`

```
data.json 읽기 → [1] 필터 로드(라벨 정규화) → [2] 패턴마다: 키에서 N 추출 → 필터 선택 → 검증 → MAC → 판정 → PASS/FAIL
```

| 함수 | 역할 |
|---|---|
| `load_json(path)` | 파일을 읽어 딕셔너리로 변환. 파일이 없거나(`FileNotFoundError`) JSON 형식이 깨져도(`JSONDecodeError`) 멈추지 않고 안내 |
| `size_from_key(key, n)` | `size_13`, `size_13_2` 같은 키를 `_`로 나눠 크기 13을 추출. 형식이 틀리면 `None` |
| `load_filters(data)` | 필터 키 `cross`/`x`를 `normalize_label()`로 `Cross`/`X`로 바꿔 `{N: {"Cross": 배열, "X": 배열}}` 형태로 정리 |
| `check_matrix(matrix, n)` | n×n 숫자 배열인지 검사. 정상이면 빈 문자열, 문제가 있으면 사유(행 개수, 열 개수, 숫자 아님)를 반환 |
| `analyze_pattern(key, item, filters)` | 패턴 하나를 검증하고 판정한 결과를 딕셔너리(점수, 판정, expected, PASS 여부, 실패 사유)로 반환 |
| `print_pattern_result(r)` | 결과 딕셔너리를 화면에 출력 |

**라벨 정규화**: 필터 키(`cross`, `x`)와 expected 값(`+`, `x`) 모두 `normalize_label()`을 거쳐 표준 라벨 `Cross`, `X`로 통일한 뒤 비교합니다. 정규화하지 않으면 `"x" == "X"`가 거짓이 되어 올바른 판정도 FAIL이 됩니다.

**케이스 단위 FAIL 처리**: `analyze_pattern()`은 아래 순서로 검사하고, 하나라도 걸리면 사유를 남기고 즉시 반환합니다. MAC 연산은 모든 검사를 통과한 경우에만 수행하므로, 크기가 다른 배열 때문에 `IndexError`로 프로그램이 멈추는 일이 없습니다.

1. 패턴 키 형식 (`size_N_idx`)
2. 해당 크기의 필터 존재 여부
3. expected 라벨이 표준 라벨로 정규화되는지
4. 패턴이 필터와 같은 n×n 숫자 배열인지
5. MAC 연산 → 판정 → expected와 비교 (동점이면 UNDECIDED로 FAIL)

계산(`analyze_pattern`)과 출력(`print_pattern_result`)을 나누고 결과를 목록으로 반환하도록 해, 결과 요약(총/통과/실패)에서 같은 데이터를 다시 사용할 수 있게 했습니다.

### 단위 확인 결과 (1단계)

| 함수 | 입력 | 결과 |
|---|---|---|
| `mac` | 십자가 × 십자가 필터 / 십자가 × X 필터 | 5 / 1 |
| `mac` | 2×2 소수 배열 | 0.9 |
| `normalize_label` | `"+"`, `" X "`, `"Cross"`, `"circle"` | `Cross`, `X`, `Cross`, `None` |
| `judge` | `(5, 1)`, `(1, 5, "Cross", "X")` | `A`, `X` |
| `judge` | `(0.9, 0.8999999999999999)` | `UNDECIDED` |
